# VDXR NR and FG release 2026.10.24

This experimental Windows x64 release reduces image copies and repeated composition
work while retaining the current NR and interpolation quality settings. It contains
the same runtime and FG DLLs validated and installed locally on October 24.

## Changes

- Write synthetic stereo images directly into their shared output atlases, removing
  the module's array-to-atlas repacking. The final host presentation copy and its
  ownership fences remain.
- Reuse the converted real BGRA image only while the exact ticket still owns it and
  the GPU has already consumed its input. Pending or invalid ownership takes the
  existing path immediately; this optimization adds no wait.
- Share phase-independent work between the two normal NVIDIA 3x synthetic images.
  Two two-target draws replace four single-target draws. Other presets, backends,
  2x, repeated frames and game-motion paths retain their existing composition paths.
- Include the previously validated input-allocation reductions, retained NR output
  texture lookup, vector-confidence baseline and bundled-runtime hook-owner lifetime
  correction used by this build.

NR coverage remains **100%** and **PGO is off**. The NR component and appearance
settings are unchanged. The standalone Controls executable is unchanged; its bundled
instructions are refreshed for this release.

## Measured scope

On an RTX 4090 at **4096 x 4096 pixels per eye**, the matched NVIDIA 3x FG
Submit-to-ready GPU interval improved by **0.695 ms, or 11.48%**, compared with the
preceding vector-confidence build. The same-build A/A median difference was
0.0036 ms. This interval excludes NR processing, host presentation, encoding,
transport and headset display; it is not an 11.48% game-FPS claim.

Direct output removes four internal repack copies and **512 MiB of temporary texture
allocations** at that 3x resolution. At 2x it removes two copies and 256 MiB.
The separate shared-composition improvement measured 0.433-0.443 ms against the
direct-output-only baseline.

Already-eligible BGRA real-frame preparation measured approximately **0.521 ms to
0.145 ms** at the same eye dimensions. In a separate 512-per-eye real-NR worker
fixture, reuse occurred in **90.68-99.15%** of measured preparations. These are
different workloads; their timings are not added into a predicted game-FPS gain.

## Install or upgrade

1. Close VR games. In Controls, select **Stock VDXR** before replacing custom files.
2. Download the runtime, Controls and matching source assets from the
   [dated release](https://github.com/jfleezy23/VirtualDesktop-OpenXR/releases/tag/nr-fg-2026.10.24).
   Verify them against `SHA256SUMS-2026.10.24.txt`.
3. Follow the [side-by-side setup](../SIDE-BY-SIDE-RUNTIME.md). For an existing
   installation, back up the custom `virtualdesktop-openxr.dll`,
   `vdxr-frame-generation.dll` and `CUSTOM-RUNTIME.json` together, then replace
   those three files in `%ProgramFiles%\VDXR-NR-FG\OpenXR`. Leave Streamer's
   official files, separately licensed NR component and saved settings in place.
4. Extract the entire Controls ZIP and open **VDXR-NR-FG-Controls.exe**, keeping
   `_internal` beside it. Accept the administrator prompt; this community app is
   unsigned. No Python installation is required.
5. Keep **VDXR** selected in Streamer and choose **Custom VDXR** in Controls.
   Set VD's **SSW Off** before using OFXR. Start with **NVIDIA**, choose **2x** or
   **3x**, and relaunch the game after changing FG mode, backend or runtime.
6. For NR, keep coverage at **100%**. NR appearance controls save automatically
   during play. NR and FG remain independent; FG also works with NR off.

The [Controls guide](../NR-FG-CONTROLS.md) explains each setting. Games must actually
reach this OpenXR runtime to use its NR/FG features; installation does not convert
every native Oculus or OpenVR title automatically.

To compare with the official runtime, close the game, select **Stock VDXR** and
launch again. To roll back this custom build, restore the backed-up matching DLL
pair and metadata with games closed. Streamer can remain open between launches.

## Validation and remaining limits

The release cohort passed 206 FG regression cases, 73 matching-host cases, 111
Python tooling tests, 480 controlled shader comparisons, 288 byte-identical public
image comparisons and two explicit GPU-based validation controls. The two native
MRT tests were rechecked after correcting their CTest exit-status handling. Seven
installed-artifact checks and eight isolated installation-transaction cases passed.

Argon, Claude, Flash and independent Codex reviewers examined the relevant source
and test changes. Final publication reviews and CI results are recorded in the pull
request. Tests establish the stated software behavior; final headset acceptance
of the combined build remains pending. Rapid-motion artifacts and ghosting can
remain. Select FG Off and restart the game if interpolation is unsuitable.

The binary build stamp identifies base revision `1d4ef2c` plus its frozen source
inputs. `BUILD.json` and the corresponding-source manifest distinguish that build
base from the later publication commit and bind the exact input hashes. The release
does not claim that these previously validated DLLs were rebuilt from a later commit.

## Source and distribution

The release includes matching corresponding source, rebuild instructions and the
applicable host, OFXR, FidelityFX and NVIDIA interface notices. The host retains its
MIT license; the optional FG module includes LGPL-3.0 components.

**No DLSSNR DLLs, neural models, proprietary streaming backend or test backend is
included or downloaded.** NR requires a separately supplied compatible licensed
component. FG with NR off does not require that component.
