# VDXR spatial NR and OFXR — October 25, 2026

This experimental Windows x64 release adds **independent NR processing resolution**. Evaluate NR at a smaller
whole-eye working size while keeping game pixel density and native output dimensions unchanged. Start with
**80% processing / 100% coverage**. Use NR with NVIDIA OFXR 3× as the starting configuration.

**[Download this release](https://github.com/jfleezy23/VirtualDesktop-OpenXR/releases/tag/nr-fg-2026.10.25)** ·
[Quick start](../NR-FG-QUICKSTART.md) · [Controls](../NR-FG-CONTROLS.md) · [Game routing](../GAME-COMPATIBILITY.md)

## Downloads and setup

- `VDXR-NR-FG-Windows-x64-2026.10.25.zip` — matching guarded runtime, FG module and `CUSTOM-RUNTIME.json`.
- `VDXR-NR-FG-Controls-Windows-x64-2026.10.25.zip` — standalone Controls app; extract the entire ZIP and keep
  `_internal` beside the EXE. No Python installation is needed.
- `VDXR-NR-FG-corresponding-source-2026.10.25.zip` — matching source, rebuild instructions and component notices.
- `SHA256SUMS-2026.10.25.txt` — asset checksums.

Use the [side-by-side setup](../SIDE-BY-SIDE-RUNTIME.md) to install under
`%ProgramFiles%\VDXR-NR-FG\OpenXR`, preserving Streamer's original files. Upgrading an existing managed install:
close VR games, choose Stock, back up the matching custom host/FG/metadata, and replace those three files together.
Keep the separately licensed NR DLL and saved preferences. Select **Custom VDXR** in Controls and **VDXR** in
Streamer afterward. Fresh settings start with NR/FG off and processing/coverage at 100%; installation preserves
existing preferences.

For the first comparison, explicitly enable NR, select **80% processing / 100% coverage**, and choose
**OFXR 3× / NVIDIA** with Virtual Desktop **SSW Off**. Relaunch after changing runtime, FG mode or backend.
Processing and appearance controls save automatically during play; there is no Apply button.

## What changed

- A **50–100% NR processing resolution** control, separate from coverage, with native **100%** as the default.
  Reduced processing prepares a smaller whole-eye input and reconstructs NR edits at native output size.
- Native 100% bypasses the new spatial GPU work. Zero NR strength preserves the original RGB. Existing model,
  style, tone, structure and skin choices remain separate; the processing slider does not replace them.
- Stereo processing and history tracking account for resolved source changes and array inputs. Failed spatial
  output is not published; existing ownership and fallback behavior remain in place.
- Updated standalone Controls, installation instructions and real UI images.

The output still passes through the existing NR/postprocessing/FG order at native dimensions. **PGO remains off.**
OFXR 2× and 3× remain available with NR on or off. NVIDIA is the default backend; FidelityFX at full resolution
remains experimental.

## Measured NR GPU work

| Native size per eye | Processing 100%, two-eye NR | Processing 80%, including reconstruction | Less NR GPU time |
| --- | ---: | ---: | ---: |
| 2048 × 2048 | 6.615 ms | 5.050 ms | About 24% |
| 3072 × 3072 | 14.374 ms | 9.643 ms | About 33% |

These RTX 4090 measurements cover isolated complete two-eye NR GPU work, with real vendor inference and the new
spatial preparation/reconstruction included at 80%. They exclude unrelated game rendering, sharpening, FG,
encoding, transport and headset display. The timed input was RGBA8 UNORM without depth. **These percentages are
not measured game-FPS gains or headset-latency reductions.** They also do not prove equal perceived detail at 80%.


## Compatibility and recovery

You need the headset version of Virtual Desktop, Windows Streamer, compatible hardware and a game routed to VDXR.
NR additionally requires a separately supplied, compatible licensed `nvngx_dlssnr.dll`.
**No proprietary NR DLL, neural model, streaming backend or test backend is included or downloaded.** Hardware NR
qualification used an RTX 4090; it does not establish every NVIDIA GPU's compatibility.

Routing Steam/OpenVR or native Oculus games can take title-specific work. See the
[routing guide](../GAME-COMPATIBILITY.md); selecting VDXR does not automatically translate every game. Frame
Launcher's separate SteamVR route is unchanged. Sniper Elite VR's fusion/stereo issue remains unresolved.

Rapid head turns, ghosting and exposure-change artifacts can remain, including with the experimental FidelityFX
backend. Select **FG Off** and restart if interpolation is unsuitable. Return NR processing to **100%** for the
native NR path, or disable NR to compare. For the official runtime, close the game, choose **Stock VDXR**, then
relaunch. To roll back this custom build, restore the backed-up matching host, FG module and metadata with games
closed. An older installation that replaced vendor DLLs needs its original backup restored or Streamer reinstalled.
