# VDXR NR and OFXR 4× — October 27, 2026

This experimental Windows x64 release adds **OFXR 4× PC frame generation** and **automatic per-game NR/FG
profiles**. NR processing resolution and coverage remain independent, including mixed settings such as
**95% coverage / 80% processing** and **90% coverage / 85% processing**. NR and FG can each be used on their own.

**[Download this release](https://github.com/jfleezy23/VirtualDesktop-OpenXR/releases/tag/nr-fg-2026.10.27)** ·
[Quick start](../NR-FG-QUICKSTART.md) · [Controls](../NR-FG-CONTROLS.md) · [Game routing](../GAME-COMPATIBILITY.md)

## Downloads and setup

- `VDXR-NR-FG-Windows-x64-2026.10.27.zip` — matching guarded runtime, FG module and `CUSTOM-RUNTIME.json`.
- `VDXR-NR-FG-Controls-Windows-x64-2026.10.27.zip` — standalone Controls app; extract the entire ZIP and keep
  `_internal` beside the EXE. No Python installation is needed.
- `VDXR-NR-FG-corresponding-source-2026.10.27.zip` — matching source, rebuild instructions and component notices.
- `SHA256SUMS-2026.10.27.txt` — asset checksums.

Follow the [side-by-side setup](../SIDE-BY-SIDE-RUNTIME.md) to install under
`%ProgramFiles%\VDXR-NR-FG\OpenXR`, preserving Streamer's official files. **4× requires the matching new host
and FG module.** To upgrade a managed installation, close VR games, choose Stock, back up the custom host,
FG module and metadata, then replace those three files together. Keep the separately licensed NR component and
saved preferences. Select **Custom VDXR** in Controls and **VDXR** in Streamer afterward.

Fresh settings start with **NR Off, FG Off, NVIDIA selected, 100% processing and 100% coverage**. Installation
preserves existing preferences. For a first comparison, explicitly enable NR, choose **95% coverage / 80%
processing** and **OFXR 4× / NVIDIA**, and turn Virtual Desktop **SSW Off**. Save if editing a game profile, then
relaunch. Runtime, FG mode and backend changes take effect on the next game session. Saved NR controls remain live.

The [October 25 release](https://github.com/jfleezy23/VirtualDesktop-OpenXR/releases/tag/nr-fg-2026.10.25)
remains available with its original assets and notes.

## What changed

- **Off / OFXR 2× / 3× / 4×** selections in Controls. 4× can add three generated frames between real frames,
  when the submission is eligible and outputs meet their deadlines. Unsupported submissions and late outputs
  preserve real-frame fallback. A saved multiplier does not prove every frame was generated or reached the headset.
- **Automatic executable profiles** for all ten NR/FG values. Use **Add game EXE…** for the actual game process,
  edit its effective settings and choose **Save game profile**. Adding or selecting an EXE writes nothing; game
  edits remain drafts until saved. Save locks all ten displayed values, including unchanged inherited values, so
  later global changes do not alter that game's saved setup. **Reset game profile** restores global inheritance.
- Profiles apply automatically when the matching EXE uses the custom runtime. Controls can be closed. There is
  no automatic library scan; select the game process rather than a launcher. Matching is by executable path, so
  games with the same EXE filename in different folders can keep separate settings.
- **Globals** retains immediate saving. Saved profile changes to NR enable, style, strength, tone, detail,
  coverage and processing refresh during play. FG mode and optical-flow backend remain session-start settings.
- Independent **50–100% processing resolution** and **10–100% effective coverage**. Reduced processing scales the
  selected centered NR rectangle and reconstructs it at native output size. Partial coverage uses a smooth crop-edge
  transition with reduced processing; game pixel density and final stereo dimensions remain unchanged.
  Processing 100% retains the native NR path. Existing combined coverage/processing and color-contract corrections
  are retained, along with saved appearance settings.

NR + FG requires **at least 90% NR coverage** for eligibility. FG with NR off does not require the proprietary
NR component. NVIDIA remains the default optical-flow backend; **FidelityFX at full resolution remains experimental**.
Keep SSW and any separate external FG layer off when using OFXR. **PGO remains off.**

## Validation scope

The exact MSVC **14.51** release binary inputs passed **225 module checks**, **110 native checks**, **165 Python
tests** and **70 Controls self-test assertions**. NVIDIA and FidelityFX both passed 4× fixtures at
**4096 × 4096 per eye**. This resolution result is fixture evidence, rather than a measured headset performance result.

A recorded **Moss** headset check used **NVIDIA 4× with NR at 90% coverage / 85% processing** and confirmed stereo,
controller response and motion. It is a bounded game check; rapid head turns, disocclusions, ghosting or exposure-change
artifacts can still occur. These checks do not establish universal game compatibility, artifact-free rendering,
a fourfold game-FPS increase or lower motion-to-photon latency. See the
[FG development guide](../../tests/frame-generation.md) for test scope and reproduction requirements.

## Compatibility and recovery

You need the headset version of Virtual Desktop, Windows Streamer, compatible hardware and a game routed to VDXR.
NR additionally requires a separately supplied, compatible licensed `nvngx_dlssnr.dll`.
**No proprietary NR DLL, neural model, streaming backend or test backend is included or downloaded.** NR hardware
qualification used an RTX 4090; it does not establish compatibility with every NVIDIA GPU.

Routing Steam/OpenVR or native Oculus games can require title-specific work. See the
[routing guide](../GAME-COMPATIBILITY.md); selecting VDXR does not automatically translate every game. Frame
Launcher's separate SteamVR route is unchanged. Sniper Elite VR's fusion/stereo issue remains unresolved.

If interpolation is unsuitable, select **FG Off**, save the game profile if applicable, and restart. NR can remain
enabled independently. To compare NR, return processing to **100%** while keeping coverage fixed, or disable NR.
If a global edit does not affect a game, check its saved profile and edit it or reset it to inherit Globals again.

To return to the official runtime, close the game, choose **Stock VDXR**, then relaunch. To roll back the custom
build, restore the backed-up matching host, FG module and metadata with games closed. Keep the licensed NR component
and saved settings. An older installation that replaced vendor DLLs needs its original backup restored or Streamer
reinstalled. Do not mix old and new host/module files for a 4× session.
