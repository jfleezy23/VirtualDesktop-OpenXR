# Smoother frame delivery — 2026.11.07.1

This experimental update improves delivery of **OFXR 2×/3×/4×** frames while the
next real frame prepares. It supports NR on and off and retains the existing
NR appearance, coverage, processing-resolution and game-profile settings.

The next producer can run during Virtual Desktop's native frame wait. Completed
images no longer reacquire that producer's context lock before presentation.
GPU completion and image ownership remain enforced; no new pacing delay, image
copy or synthesis pass was added. The retained NVIDIA/FidelityFX FG module is
unchanged by this handoff update.

## Install or upgrade

Download the matching **runtime ZIP** and **Controls ZIP**, verify the supplied
SHA-256 checksums, and extract each completely. The standalone Windows Controls
EXE needs no Python installation; keep its `_internal` folder beside it.

Follow the [illustrated quickstart](../NR-FG-QUICKSTART.md) and
[side-by-side upgrade instructions](../SIDE-BY-SIDE-RUNTIME.md). Close games,
select Stock in Controls, back up the existing external runtime, then replace
the two runtime DLLs and their matching `CUSTOM-RUNTIME.json`. Preserve your
separately licensed NR component and saved profiles. Select Custom for the next
game launch; keep VDXR selected in Streamer and turn VD's SSW off for OFXR.

**No proprietary NR DLL, neural model or streaming backend is included or
downloaded.** Ordinary FG with NR off does not require the NR component.

Choose **OFXR 2×, 3× or 4×** in Controls and restart the game after changing the
multiplier. Keep your preferred appearance and processing settings. Game
profiles override global settings when saved; edit the actual game executable's
profile. See the [Controls guide](../NR-FG-CONTROLS.md).

Games must actually reach VDXR. Some Steam titles need a compatible OpenVR-to-OpenXR
bridge, while Oculus titles may need an Oculus-to-OpenXR bridge or an available
OpenXR backend. Store ownership alone does not identify the graphics API. Keep a
working original launch route and consult the [routing guide](../GAME-COMPATIBILITY.md).

## Validation and limits

Release and ReleaseBundle x64 builds and same-tool analyzer comparisons passed
with MSVC 14.51.36231, `/fp:precise` and PGO disabled. The Controls EXE is checked
locally in an isolated registry environment before packaging.

The fresh source cohort passed 66 controlled GPU cases across 2×/3×/4×,
NR on/off and D3D11/D3D12, plus 30 CPU/loader cases and 167 tooling tests.
Controlled tests are separate from physical-headset qualification.

Aircar steady-flight native handoffs became more regular in the observed test,
and the headset run was reported smoother. The later capture used a higher
resolution; scene and connection were not controlled. This is not a claim of
measured end-to-end headset latency or guaranteed frame rates. Deliberate
resolution changes can still hitch. See [pacing evidence](../frame-delivery-pacing.md).

The source package includes the retained module recipe and corresponding source;
build provenance distinguishes the freshly compiled host from the retained FG
binary. Runtime ZIPs, source ZIPs and Controls ZIPs serve different purposes—use
the runtime and Controls packages to play.
