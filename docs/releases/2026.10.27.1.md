# Earlier frame handoff and NR/FG Controls — October 27, 2026

This Windows x64 update sends the first generated stereo image to Virtual Desktop without waiting for the
rest of a split synthesis group. It keeps your NR appearance, processing resolution, coverage and game profiles.
The Controls app includes the runtime switcher, NR settings and **Off / OFXR 2× / 3× / 4×** choices.

## Download and upgrade

- `VDXR-NR-FG-Windows-x64-2026.10.27.1.zip` — the matching runtime DLL, FG DLL and `CUSTOM-RUNTIME.json`.
- `VDXR-NR-FG-Controls-Windows-x64-2026.10.27.1.zip` — the standalone Controls app and illustrated guides.
  Extract the entire ZIP and keep `_internal` beside `VDXR-NR-FG-Controls.exe`; no Python installation is needed.
- `VDXR-NR-FG-corresponding-source-2026.10.27.1.zip` — matching source, generated derivative, dependencies and notices.
- `SHA256SUMS-2026.10.27.1.txt` — checksums. `BUILD-2026.10.27.1.json` and `BUILD-SOURCE-2026.10.27.1.md`
  describe the exact tested binaries and rebuild inputs.

1. Close VR games and choose **Stock VDXR** in Controls. Back up your custom host DLL, FG DLL and metadata.
2. Follow the [side-by-side installation](../SIDE-BY-SIDE-RUNTIME.md). Replace those three files together under
   `%ProgramFiles%\VDXR-NR-FG\OpenXR`. Leave Streamer's official files, your separately licensed NR component,
   folder permissions and saved preferences in place. A first installation also needs the guide's registration step.
3. Extract Controls into its own folder and run the EXE. Choose **Custom VDXR** there and **VDXR** in Streamer.
   Disable VD's **SSW** and any separate FG layer when using OFXR.
4. Select Globals or add the actual game EXE. To try NR, enable it explicitly; **100% coverage / 80% processing**
   is a useful first comparison. Choose NVIDIA and the desired FG mode. Globals save automatically; game edits
   require **Save game profile**. Relaunch after changing runtime, FG mode or backend.

Fresh settings are still **NR Off, FG Off, NVIDIA, 100% coverage and 100% processing**. Installation preserves
existing choices. Saved NR settings can change during play; FG mode and backend apply at the next game session.
The Controls EXE is unchanged from the preceding release; this package refreshes its guides and screenshots.

## What changed

- Earlier S1 handoff on paths that generate later images separately: NVIDIA 4× and FidelityFX 3×/4×.
- Later images retain their own completion wait, and resource lifetime still waits for the entire group.
- A late synthesis tail can fall back to protected real-frame pixels. Future producer work stays behind the
  current group's prepared presentation copies.
- NVIDIA's joint 3× composition and the unsplit 2× path remain intact. No new setting is needed.
- NR shaders, the separately supplied model, color processing, coverage and appearance were not changed.
  **PGO remains off.**

NR and FG work independently. With NR enabled, FG requires at least **90% coverage** for eligibility.
FidelityFX at full resolution remains experimental; NVIDIA is the default. Generated frames can still have
motion/disocclusion artifacts, and a multiplier does not guarantee matching game FPS or lower headset latency.
Some delays in VD's native submission calls remain.

## Profiles and game routes

Use **Add game EXE…** for the executable that runs the game, then save the complete working NR/FG setup.
Controls can be closed afterward. **Reset game profile** restores global inheritance; an existing saved profile
can override later global changes. The runtime switcher applies to the installation, rather than one profile.

Some Steam/OpenVR and native Oculus titles need a compatible OpenXR translation route or a title-specific fix.
Selecting VDXR does not translate every game automatically. Use the [routing guide](../GAME-COMPATIBILITY.md)
and retain a working original launch. A successful route does not guarantee a useful NR effect.
This release does not supply a Steam Frame streaming runtime or change Frame Launcher's SteamVR route.

## What was checked

The runtime and FG DLLs are the same binaries tested locally. Moss was checked at 120 Hz with NVIDIA and NR
in 2×, 3× and 4×; stereo and controls worked and motion was reported smooth. The 4× capture was a short startup
window. Controlled GPU tests also cover 120/144 Hz and both backends; these do not measure physical scanout.
The [development guide](../../tests/frame-generation.md) records detailed validation and reproduction scope.
No universal compatibility, artifact-free motion or sustained FPS gain is claimed.

## Return to stock or roll back

Close the game, choose **Stock VDXR**, then relaunch. To roll back the custom build, restore the backed-up host,
FG DLL and metadata together while games are closed. Keep the licensed NR component and saved settings.
The [previous release](https://github.com/jfleezy23/VirtualDesktop-OpenXR/releases/tag/nr-fg-2026.10.27)
remains available unchanged.
